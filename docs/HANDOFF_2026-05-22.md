## Critical things to know before you touch anything

1. **The kernel now has a global allocator** (`cb6c726`): the 16 MiB
   `kernel_core::memory::heap` arena, wired as `#[global_allocator]` in
   `kernel-x86_64/src/main.rs`. So `Box`/`Vec`/`String` work in the *binary*
   crate (and any kernel-x86_64 dep). `kernel-core` itself is still written
   no-alloc. Heap is init'd at `main.rs` boot before any allocation.

2. **task#40 is fixed — context_switch is now atomic.** The long-standing
   intermittent #PF/#DF was a *torn context switch*: `context_switch` ended
   with `popfq; jmp`, leaving a 1-instruction IF=1 window where a timer
   preempted the half-done switch. Now it transfers via `IRETQ`
   (rip+rflags+rsp atomically, IF stays 0 until then). If you touch
   `context_switch` or `schedule()`, **do not reintroduce a preemptible
   window** — keep the IRETQ. See `project_semantic_os_task40.md`.

3. **BUILD GOTCHA (cost hours this session):** build the image with
   `cargo run --release` **from `x86_64-runner/`**. From `kernel-x86_64/` it
   errors `%1 is not a valid Win32 application` and silently leaves a STALE
   image — you debug a phantom. Canonical loop:
   ```
   (user prog changed?)  cd <prog>/ && cargo build --release
   cd kernel-x86_64/  && cargo build --release      # compile kernel
   cd x86_64-runner/  && cargo run --release         # ← build the image HERE
   cd <repo root>     && qemu ... (absolute paths)
   ```

4. **std-shim Ring-3 programs MUST build at `opt-level=0`** (#54): any
   optimization miscompiles the `asm!` syscall wrappers. Copy an existing
   `user-programs/*/Cargo.toml` `[profile.release]` verbatim.

5. **QEMU invocations** (Windows host):
   ```
   # standard:
   qemu-system-x86_64 -cpu max \
     -drive format=raw,file=<repo>\kernel-x86_64\target\x86_64-unknown-none\release\semantic-os-x86_64-bios.img \
     -drive if=virtio,format=raw,file=<repo>\vdisk.img \
     -device qemu-xhci -device usb-kbd -m 256M -serial stdio -display none -no-reboot
   # add networking (DNS/TCP demos 16/34/36): -netdev user,id=net0 -device virtio-net-pci,netdev=net0
   ```
   `-cpu max` is required (RDRAND). DEMO `PASS:`/`FAIL:` lines grep out of the
   serial log; that's the validation method (no `cargo test` for kernel-core).

6. **GDB-on-QEMU works** for hard bugs: `qemu ... -S -gdb tcp::1234`, then
   Inkscape's gdb (`/x/Applications/Inkscape/bin/gdb`). Runtime addr = ELF
   symbol + `0x10000000000`. But reading the 21 MB `.bss` through a faulting
   process CR3 fails — prefer dumping from the #DF handler / serial prints
   (the bug is deterministic and survives instrumentation now).

The committed north star is **Phase 13 self-development loop** + **Phase 14
self-hosting**. Nothing below is hardware-blocked — all run in QEMU.

1. **M19 TTY layer** — bidirectional console: stdin from the USB keyboard
   (M3 done), ANSI escapes, scrollback, per-process stdio. Gateway to
